### Предисловие

Список инструкций предоставляет исключительно краткое описание инструкций и их предназначения. Подробное описание предназначения инструкций и требования к их аргументах предоставляются в других файлах:
- Модульная составляющая
	- Характеристика и требования - [Модуль / Заголовок](/Модуль/Заголовок.md).
- Программная составляющая

### Список модульной составляющей

#### `<file>`

- `(module "type" <module (0)> <module (N)>)` - оглавление определения модуля, принимает тип определения (*"type"*) в формате строки, на данный момент поддерживается только `vtl/module`, после принимает неявный список параметров модуля (*`<module (0)> <module (N)>`*).

#### `<module>`

- `(name "name")` - определение имени модуля, принимает имя (*`"name"`*) в формате строки, может быть только одно на всё определение модуля.
- `(version "version")` - определение версии модуля, принимает версию (*`"version"`*) в формате строки, может быть только одно на всё определение модуля.
- `(friend-access [ "friend (0)" "friend (N)" ])` - определение перечисления запросов дружеского доступа, принимает список модулей-друзей (*`[ "friend (0)" "friend (N)" ]`*), может быть определено несколько раз, каждый раз определения расширяет общий список.
- `(friend-export [ "<friend-export (0)> <friend-export (N)>" ])` - определение перечисления конкретных модулей и правил определения модулей-друзей, принимает список инструкций типа `<friend-export>` (*`[ "<friend-export (0)" "<friend-export (N)>" ]`*), может быть определено несколько раз, каждый раз определения расширяет общий список.
- `(dependencies [ <dependency (0)> <dependency (N)> ])` - определение перечисления зависимостей модуля, принимает список инструкций типа `<dependency>` (*`[ <dependency (0)> <dependency (N)> ]`*), может быть определено несколько раз, каждый раз определения расширяет общий список.
- `(allow-export <flag>)` - явное указание экспорта модульных единиц, принимает разрешение (*`<flag>`*).
- `(allow-mixin-define <flag>)` - явное указание возможности модуля определять примеси, принимает разрешение (*`<flag>`*).
- `(allow-mixin-apply <flag>)` - явное указание возможности модуля на применение к нему примесей, принимает разрешение (*`<flag>`*).
- `(sources "source (0)" "source (N)")` - определение перечисления файлов исходного кода модуля, принимает неявный список путей (*`"source (0)" "source (N)"`*) до файлов относительно заголовка модуля (*`module.vtl`*).
- `(resources "source (0)" "source (N)")` - определение перечисления файлов ресурсов кода модуля, принимает неявный список путей (*`"source (0)" "source (N)"`*) до файлов относительно заголовка модуля (*`module.vtl`*).

#### `<friend-export>`

- `(module "name" ?<friend-allow-mixin>)` - конкретный дочерний модуль, принимает имя дочернего модуля (*"name"*), может принять инструкцию типа `<friend-allow-mixin>` (*`?<friend-allow-mixin>`*).
- `(rule "regex" ?<friend-allow-mixin>)` - правило определения дочерних модулей, принимает регулярное выражение (*`"regex"`*) в формате строки для верификации имён дочерних модулей, может принять инструкцию типа `<friend-allow-mixin>` (*`?<friend-allow-mixin>`*).

##### `<friend-allow-mixin>`

- `(allow-mixin <flag>)` - явное указание возможности модуля-друга применения примесей к модулю, принимает разрешение (*`<flag>`*).

#### `<dependency>`

- `"name@version"` - определение зависимости, принимает имя и версию (*"name@version"*) разделённые через `@` в формате строки.
- `(module (name "name") (version "version") ?<dependency-allow-mixin>)` - определение зависимости, принимает имя (*`(name "name")`*) и версию (*`(version "version")`*) в формате инструкций принимающих одну строку соответствующего параметра, может принять инструкцию типа `<dependency-allow-mixin>` (*`?<dependency-allow-mixin>`*).

##### `<dependency-allow-mixin>`

- `(allow-mixin <flag>)` - явное указание возможности зависимости применения примесей к модулю, принимает разрешение (*`<flag>`*).

#### `<flag>`

- `allow` - разрешение.
- `deny` - запрет.

### Список программной составляющей

#### `<file>` / `<internal>`

- `(class name parent [ impl(0) impl(N) ] <class (0)> <class (N)>)` - определение класса, принимает имя класса (*`name`*), имя родительского класса (*`parent`*), список реализуемых интерфейсов (*`[ impl(0) impl(N) ]`*), после принимает неявный список инструкций описания тела класса (*`<class (0)> <class (N)>`*).
- `(interface name [ parent(0) parent(N) ] <interface (0)> <interface (N)>)` - определение интерфейса, принимает имя интерфейса (*`name`*), список родительских интерфейсов (*`[ parent (0) parent (N) ]`*), после принимает неявный список инструкций описания тела интерфейса (*`<interface (0)> <interface (N)>`*).

- `(struct name <struct (0)> <struct (N)>)` - определение структуры, принимает имя структуры (*`name`*), после принимает неявный список инструкций описания тела структуры (*`<struct (0)> <struct (N)>`*).

- `(def-fun name ^ret [[arg-name(0) ^arg-type(0)][arg-name(N) ^arg-type(N)]] <func (0)> <func (N)>)` - определение функции, принимает имя метода (*`name`*), возвращаемый тип (*`^ret`*), список аргументов в формате пары имя / тип (*`[[arg-name(0) ^arg-type(0)][arg-name(N) ^arg-type(N)]]`*), после принимает неявный список инструкций описания тела функции (*`<func (0)> <func (N)>`*).

#### `<file>`

- `(@internal <internal (0)> <internal (N)>)` - модификатор внутренней модульной единицы, принимает неявный список определений модульных единиц (*`<internal (0)> <internal (N)>`*).

- `(namespace name <file (0)> <file (N)>)` - определение пространства имён, принимает имя пространства имён (*`name`*), после принимает неявный список определений модульных единиц (*`<file (0)> <file (N)>`*) входящих в данное пространство имён. 

- `(mixin name target priority <mixin>)` - определение примеси, принимает имя примеси (*`name`*), имя цели (*`target`*), приоритет (*`priority`*), после принимает неявный список инструкций описания тела класса (*`<mixin (0)> <mixin (N)>`*).

#### `<mixin>` / `<class>` / `<interface>` / `<struct>` / `<internal>` / `<static>`

- `(def-fun name ^ret [[arg-name(0) ^arg-type(0)][arg-name(N) ^arg-type(N)]] <func (0)> <func (N)>)` - определение метода, принимает имя метода (*`name`*), возвращаемый тип (*`^ret`*), список аргументов в формате пары имя / тип (*`[[arg-name(0) ^arg-type(0)][arg-name(N) ^arg-type(N)]]`*), после принимает неявный список инструкций описания тела функции (*`<func (0)> <func (N)>`*).

- `(def-set-prop name ^type <func (0)> <func (N)>)` - определение сеттера свойства, принимает имя свойства и тип, после принимает неявный список инструкций описания тела сеттера.
- `(def-get-prop name ^type <func (0)> <func (N)>)` - определение геттера свойства, принимает имя и тип свойства, после принимает неявный список инструкций описания тела сеттера.

#### `<mixin>` / `<class>` / `<struct>` / `<internal>` / `<static>`

- `(def-field name ^type)` - определение поля, принимает имя и тип поля.

#### `<class>` / `<struct>`

- `(@static <static (0)> <static (N)>)` - модификатор статического члена класса / структуры, принимает неявный список определений членов класса / структуры (*`<static (0)> <static (N)>`*).

#### `<mixin>`

- `(set-parent name)` - установка родительского класса, принимает имя нового родительского класса (*`name`*).
- `(set-impl name(0) name(N))` - установка новых реализуемых интерфейсов, принимает неявный список имён новых реализуемых интерфейсов (*`name(0) name(N)`*).
- `(expand-impl name(0) name(N))` - расширение списка реализуемых интерфейсов, принимает неявный список имён новых реализуемых интерфейсов (*`name(0) name(N)`*).
- `(reduce-impl name(0) name(N))` - сужение списка реализуемых интерфейсов, принимает неявный список имён удаляемых реализуемых интерфейсов (*`name(0) name(N)`*).

- `(del-defn name)` - удаление метода, принимает имя метода (*`name`*).
- `(del-field name)` - удаление поля, принимает имя поля (*`name`*).
- `(del-set-prop name)` - удаление сеттера, принимает имя сеттера (*`name`*).
- `(del-get-prop name)` - удаление геттера, принимает имя геттера (*`name`*).

#### `<func>`

- `(new ^type arg(0) arg(N))` - создание нового объекта с последующим вызовом его конструктора, принимает тип объекта (*`^type`*), после принимает неявный список аргументов (*`arg(0) arg(N)`*) для передачи в конструктор.

- `(call-super ^type name arg(0) arg(N))` - вызов метода собственного родителя, принимает тип родителя (*`^type`*), имя метода (*`name`*) после принимает неявный список аргументов вызова (*`arg(0) arg(N)`*), возвращает результат вызова.
- `(call object name arg(0) arg(N))` - вызов метода объекта, принимает объект (*`object`*), имя метода (*`name`*) после принимает неявный список аргументов вызова (*`arg(0) arg(N)`*), возвращает результат вызова.
- `(call ^type name arg(0) arg(N))` - вызов статического метода типа, принимает тип (*`type`*), имя метода (*`name`*) после принимает неявный список аргументов вызова (*`arg(0) arg(N)`*), возвращает результат вызова.

- `(set-field object field value)` - установка значения в поле объекта (*приоритетно через вызов сеттера*), принимает объект (*`object`*), имя поля (*`field`*) и значение для установки (*`value`*).
- `(set-field ^type field value)` - установка значения поля типа (*приоритетно через вызов сеттера*), принимает тип (*`^type`*), имя поля (*`field`*) и значение для установки (*`value`*).
- `(get-field object field)` - получение значения поля объекта (*приоритетно через вызов геттера*), принимает объект (*`object`*) и имя поля (*`field`*), возвращает значение поля (*либо результат вызова геттера*).
- `(get-field ^type field)` - получение значения статического поля типа (*приоритетно через вызов геттера*), принимает тип (*`^type`*) и имя поля (*`field`*), возвращает значение поля (*либо результат вызова геттера*).

- `(is object ^type)` - проверка принадлежности объекта типу, принимает объект (*`object`*) и тип (*`^type`*), возвращает логическое значение соответствия.
- `(as object ^type)` - приведение объекта к типу, принимает объект (*`object`*) и тип (*`^type`*), возвращает итоговый объект или кидает исключение при ошибке приведения.
- `(as value ^type)` - приведение значения к типу, принимает значение (*`value`*) и тип (*`^type`*), возвращает значение нового типа.

- `(add value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией сложения. Возвращает сумму элементов списка.
- `(sub value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией вычитания. Возвращает результат последовательного вычитания: `value(0) - value(1) - … - value(N)`.
- `(mul value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией умножения. Возвращает произведение элементов списка.
- `(div value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией деления. Возвращает результат последовательного деления: `value(0) / value(1) / … / value(N)`.

- `(pow value(0) value(N))` — левая свёртка неявного списка `value(0) … value(N)` как минимум из двух элементов бинарной операцией возведения в степень. Возвращает результат последовательного возведения в степень: `pow(value(0), value(1))`, затем `pow(результат, value(2))` и т.д.
- `(mod value(0) value(N))` — левая свёртка неявного списка `value(0) … value(N)` как минимум из двух элементов бинарной операцией взятия остатка от деления. Возвращает результат последовательного применения `mod`: `mod(value(0), value(1))`, затем `mod(результат, value(2))` и т.д.

- `(not value)` — унарная логическая операция *НЕ*. Принимает значение и возвращает его логическую инверсию.
- `(and value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной логической операцией *И*. Возвращает результат последовательного применения *И*: `value(0) AND value(1) AND … AND value(N)`.
- `(or value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной логической операцией *ИЛИ*. Возвращает результат последовательного применения *ИЛИ*: `value(0) OR value(1) OR … OR value(N)`.
- `(xor value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной логической операцией *ИСКЛ-ИЛИ*. Возвращает результат последовательного применения *ИСКЛ-ИЛИ*: `value(0) XOR value(1) XOR … XOR value(N)`.

- `(bit-not value)` — унарная битовая операция *побитового НЕ. Принимает значение и возвращает его инверсию всех битов.
- `(bit-and value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией побитового *И. Возвращает результат последовательного применения *И*: `value(0) & value(1) & … & value(N)`.
- `(bit-or value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией побитового *ИЛИ*. Возвращает результат последовательного применения *ИЛИ*: `value(0) | value(1) | … | value(N)`.
- `(bit-xor value(0) value(N))` — левая свёртка непустого неявного списка `value(0) … value(N)` бинарной операцией побитового *ИСКЛ-ИЛИ*. Возвращает результат последовательного применения *ИСКЛ-ИЛИ*: `value(0) ^ value(1) ^ … ^ value(N)`.

- `(bit-shift-left value(0) value(N))` — левая свёртка неявного списка `value(0) … value(N)` бинарной операцией *побитового сдвига влево*. Первый элемент — начальное значение аккумулятора, каждый следующий элемент — количество битов для очередного сдвига влево. Возвращает результат последовательного сдвига: `((...(value(0) << value(1)) << value(2)) ... << value(N))`. Если список состоит из одного элемента, возвращается `value(0)`.
- `(bit-shift-right value(0) value(N))` — левая свёртка неявного списка `value(0) … value(N)` бинарной операцией *побитового сдвига вправо*. Первый элемент — начальное значение аккумулятора, каждый следующий элемент — количество битов для очередного сдвига вправо. Возвращает результат последовательного сдвига: `((...(value(0) >> value(1)) >> value(2)) ... >> value(N))`. Если список состоит из одного элемента, возвращается `value(0)`.
