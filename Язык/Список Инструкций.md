### Предисловие

Список инструкций предоставляет исключительно краткое описание инструкций и их предназначения. Подробное описание предназначения инструкций и требования к их аргументах предоставляются в других файлах:
- Модульная составляющая
	- Характеристика и требования - [Модуль / Заголовок](/Модуль/Заголовок.md).
- Программная составляющая

### Список модульной составляющей

#### `<file>`

- `(module "type" <module (0)> <module (N)>)` - оглавление определения модуля, принимает тип определения (*"type"*) в формате строки, на данный момент поддерживается только `vtl/module`, после принимает неявный список параметров модуля (*`<module (0)> <module (N)>`*).

#### `<module>`

- `(name "name")` - определение имени модуля, принимает имя (*`"name"`*) в формате строки, может быть только одно на всё определение модуля.
- `(version "version")` - определение версии модуля, принимает версию (*`"version"`*) в формате строки, может быть только одно на всё определение модуля.
- `(parents [ "parent (0)" "parent (N)" ])` - определение перечисления родительских модулей модуля, принимает список родительских модулей (*`["parent (0)] "parent (N)"`*), может быть определено несколько раз, каждый раз определения расширяет общий список.
- `(childs [ <child (0)> <child (N)> ])` - определение перечисления правил и конкретных дочерних модулей модуля, принимает список инструкций типа `<child>` (*`[<child (0)> <child (1)>]`*), может быть определено несколько раз, каждый раз определения расширяет общий список.
- `(dependencies [ <dependency (0)> <dependency (N)> ])` - определение перечисления зависимостей модуля, принимает список инструкций типа `<dependency>` (*`[<dependency (0)> <dependency (N)>]`*), может быть определено несколько раз, каждый раз определения расширяет общий список.
- `(allow-export <flag>)` - явное указание экспорта модульных единиц, принимает разрешение (*`<flag>`*).
- `(allow-mixin-define <flag>)` - явное указание возможности модуля определять примеси, принимает разрешение (*`<flag>`*).
- `(allow-mixin-apply <flag>)` - явное указание возможности модуля на применение к нему примесей, принимает разрешение (*`<flag>`*).
- `(sources "source (0)" "source (N)")` - определение перечисления файлов исходного кода модуля, принимает неявный список путей (*`"source (0)" "source (N)"`*) до файлов относительно заголовка модуля (*`module.vtl`*).
- `(resources "source (0)" "source (N)")` - определение перечисления файлов ресурсов кода модуля, принимает неявный список путей (*`"source (0)" "source (N)"`*) до файлов относительно заголовка модуля (*`module.vtl`*).

#### `<child>`

- `(module "name" ?<child-allow-mixin>)` - конкретный дочерний модуль, принимает имя дочернего модуля (*"name"*), может принять инструкцию типа `<child-allow-mixin>` (*`?<child-allow-mixin>`*).
- `(rule "regex" ?<child-allow-mixin>)` - правило определения дочерних модулей, принимает регулярное выражение (*`"regex"`*) в формате строки для верификации имён дочерних модулей, может принять инструкцию типа `<child-allow-mixin>` (*`?<child-allow-mixin>`*).

##### `<child-allow-mixin>`

- `(allow-mixin <flag>)` - явное указание возможности дочернего модуля применения примесей к модулю, принимает разрешение (*`<flag>`*).

#### `<dependency>`

- `"name@version"` - определение зависимости, принимает имя и версию (*"name@version"*) разделённые через `@` в формате строки.
- `(module (name "name") (version "version") ?<dependency-allow-mixin>)` - определение зависимости, принимает имя (*`(name "name")`*) и версию (*`(version "version")`*) в формате инструкций принимающих одну строку соответствующего параметра, может принять инструкцию типа `<dependency-allow-mixin>` (*`?<dependency-allow-mixin>`*).

##### `<dependency-allow-mixin>`

- `(allow-mixin <flag>)` - явное указание возможности зависимости применения примесей к модулю, принимает разрешение (*`<flag>`*).

#### `<flag>`

- `allow` - разрешение.
- `deny` - запрет.
