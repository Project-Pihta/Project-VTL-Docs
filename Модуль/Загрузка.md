### Описание

Все модули **`VTL`** за исключением *системных* загружаются через *загрузчик модулей*. Система **`VTL`** поддерживает динамическую загрузку модулей.

При загрузке модуля должны выполняться несколько требований:
- *Родительские* модули должны содержать *указание модуля* или *правило* разрешающие определение загружаемого модуля как *дочернего*. Иначе будет произведена ошибка загрузки модуля.
- *Зависимости* загружаемого модуля загружаются вместе с модулем. Уже загруженные зависимости проверяются на совместимость по версиям, если версия является допустимой - пропуск загрузки, иначе - ошибка загрузки загружаемого модуля. В случае ошибки загрузки зависимости приводит к ошибке загрузки самого загружаемого модуля.
- *Примеси* не могут быть применены для уже загруженного модуля. Примеси могут быть сохранены для отложенного применения, если целевой модуль не является загруженным / загружаемым. В случае, если примесь пытается примениться к загружаемому модулю - это приводит к ошибке загрузке модуля.

Загрузка модуля выполняется в несколько этапов:
1. Запрос модуля из поставщика модулей.
2. Запрос незагруженных зависимостей модуля из поставщика модулей.
3. Проверка родительских модулей на возможность иметь дочерний модуль.
4. Группировка загружаемых модулей для параллельной обработки.
5. Парсинг исходного кода загружаемых модулей в АСД (*параллельный для всех модулей*).
6. Первичная обработка примесей:
	1. Выделение примесей из АСД.
	2. Проверка целей на загруженность (*нельзя применять примеси к загруженным модулям*) и выделение примесей для отложенного применения.
7. Семантический анализ АСД в семантический граф с последующим применением примесей (*параллельный для групп модулей*).
8. Компиляция семантического графа в байт-код **`VTL`**.
9. Определение модулей в системе.
