### Описание

*`Project VTL`* - виртуальная машина и язык программирования, предназначенные для построения компиляторов и сред выполнения с акцентом на надёжность, безопасность и расширяемость. Программы на **VTL** выполняются на виртуальной машине, что обеспечивает переносимость между операционными системами без перекомпиляции.

### Концепт идея

#### Модульная система

**`Модуль`** - основная единица организации кода. Модуль содержит определения **модульных единиц** (*функций, структур, классов, интерфейсов и примесей*). 
Модуль определяет **область видимости** своих элементов и управляет **доступом** к ним на межмодульном уровне:
- Модуль может указать, какие другие модули (*или их группы*) имеют право **читать** его элементы.
- Модуль может указать, какие модули имеют право **изменять** его элементы (*через примеси*).
- Все элементы внутри модуля являются общедоступными для самого модуля (*модификаторы доступа на уровне модульных единиц отсутствуют*).
Модули поддерживают **наследование**:
- Модуль может разрешать или запрещать создание наследников от себя.
- Наследник получает **право чтения** всех элементов родителей (*родитель не может запретить это*).
- Родитель может **запретить** наследнику **изменять** свои элементы (*т.е. запретить примеси*).
- Наследник имеет собственные правила доступа к своим элементам (*может разрешать или запрещать чтение и изменение для других модулей*).

**`Пространство имён`** - логический контейнер, группирующий модульные единицы по смыслу. Пространство имён может быть вложенным. Разные модули могут определять одно и тоже пространство имён, т.к. обращение к модульным единицам происходит начиная с названия модуля.

#### Модульные единицы

**`Функции`** - именованный блок кода, принимающий параметры и возвращающий значение. Функции могут быть глобальными (*принадлежать модулю*), методами (*принадлежащими классу*) или абстрактными методами (*см. "**Интерфейс**"*).

**`Структура`** - составной тип, содержащий только поля. Структура не содержит методов, конструктора и деструктора, не поддерживает наследование и реализацию интерфейсов. Поля инициализируются при создании и являются неизменяемыми. Используется для представления простых агрегатов.

**`Класс`** - составной тип, объединяющий данные (*поля*) и поведение (*методы*). Класс может иметь конструктор и деструктор. Поддерживает **единичное наследование** (*один родительский класс*) и реализацию нескольких интерфейсов.

**`Интерфейс`** - контракт, определяющий набор методов и свойств, которые класс обязуется реализовать. Интерфейсы не могут быть инстансированы. Могут содержать реализации методов по умолчанию (*класс может их переопределить или использовать как есть*). Поддерживает множественное наследование интерфейсов.

**`Примесь`** - модульная единица, содержащая набор **инструкций по изменению** существующих модульных единиц внутри целевого модуля. Примесь может:
- **Добавлять** новые модульные единицы в модуль.
- **Изменять** (*добавлять, заменять или удалять*) существующие модульные единицы модуля.
Примесь не изменяет исходного кода целевого модуля, её действие применяется на уровне загрузки модулей.
